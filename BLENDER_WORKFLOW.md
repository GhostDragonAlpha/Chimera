## Edit, inspect and replay

1. Open the viewport sidebar with **N**, then **Chimera > Membrane Assembly**. The starter already has three films and two apex connections; do not add another starter over it.
2. Inspect the saved construction. **Resume Saved GPU Matter** creates Studio's private helper. Apply a modest center load (the tested starting value is 0.8 N) and inspect its shape.
3. **Show Native Render in Image Editor** displays the native raster. With **Match Blender View** checked, Blender's perspective orbit and pivot are converted through the same `(x,y,z) -> (x,z,-y)` axis map as the kernel's render vertices. Native pose readback and world-point projections are checked. Repeating the same view succeeds; native physical state, Edit Mode and unfinished source edits stay intact. The renderer retains its fixed 45-degree vertical FOV and upright/no-roll camera, so framing can differ; the panel explains this. Orthographic and camera-object views refuse. Supported orbit distance starts at 1 m (native scene bounds can impose a larger minimum); native clipping is 0.1-1000 m and the raster is 384x256. Uncheck **Match Blender View** for the established fixed camera; its full pose is reset. Shift-F5 returns an Image Editor to the 3D viewport.
4. Use **Return to Matter Authoring** before editing geometry, assignments or connections. Select source films, assign a common surface tension, and **Build Connected Films**. Viewport colors identify pieces; they do not define material laws. Joined films currently need uniform tension.
5. Mark the free apex for supported fans, connect coincident apices explicitly, and keep rim supports. After duplicating a source, use **Make Selected Films New Instances** before connecting it. Blender performs modeling; the existing compiler decides whether the construction is supported.
6. Use **Replay Native Checkpoint** to compare confirmed samples. Continuing branches from that sample. Rejected edits must leave the confirmed sample intact.
7. Save the .blend. **Save GPU Matter Trial** exports native state and construction; **Open GPU Matter Trial** can reconstruct source films. The starter .matter.json is a recovery example, not an automatically updated sidecar of every save.
8. **Release Studio GPU Memory** closes Studio's helper. The saved checkpoint remains. Closing Blender also closes its owned helper.

The .blend/.matter.json retain the confirmed physical/render sample and construction, not the whole session's checkpoint history. The bounded replay slider is a session tool, not Blender's animation timeline. Reopening does not silently recompute, migrate versions or start simulation.

## Integrate existing Blender modes and workspaces

Operator direction, 2026-10-19: humans and AI use the same Blender systems.
Modeling is a workspace; Object/Edit/Sculpt/Paint/Pose are modes. Editors such as
the Outliner, Properties, Geometry Nodes and Image Editor provide the relevant
controls. Changing mode/workspace alone never compiles or advances native matter.

Start with Object Mode for placement/instances/connections, Edit Mode for
supported film geometry and apex selection, Properties for explicit physical
material assignment, and the existing Image Editor/native-view handoff.
Geometry Nodes/modifiers can later generate explicit compiler inputs. General material painting,
sculpting and posing need mappings to supported regions, topology and native laws;
their visual results do not automatically supply those behaviors. Keep editable
sources and the last accepted native result distinct.

The AI calls the same operation implementation as UI buttons. Resolve UUIDs,
selection, mode, editor and source/native revision; check context and poll
requirements, deliberately switch when needed, synchronize edits and inspect the
result. Perform Blender data changes on its main thread. Preserve incidental
selection/view, and detect user edits before applying an outdated proposal.
Reuse blocks_ui.py's existing operators/edit-mode synchronization and
gpu_workspace.py's checkpoint lifecycle.

Tie Blender undo to explicit native recovery where required; ordinary Blender
undo cannot rewind an external process by itself. Track asynchronous commands
through queued/running/succeeded/failed states; submission is not confirmed
completion. Keep a failed or uncertain call recoverable without automatic
duplicate mutations. The fuller mapping and acceptance examples are in the
main GAME_PLAN_ACTION_RPG.md §12.2. The Object/Edit subset and the painted support/seam mapping below are implemented; broader adapters remain planned.
