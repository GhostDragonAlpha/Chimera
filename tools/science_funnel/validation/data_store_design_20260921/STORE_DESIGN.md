## 0. RULE 0 — the theory, in one line

**STATEMENT:** RAW acquired datasets and bulk extracted model geometry can live outside git in a
plain sha256-addressed store (`E:/ChimeraData/store/`), with a committed index manifest and a
one-module resolution layer, and every proof the funnel makes survives unchanged.

**PREDICTION:** the pilot (wiseman2026) runs every gate green with every sha pin verifying from
store-resolved bytes; phases 2–3 shrink a fresh clone's data checkout by ≥ 300 MB with
`pin_crosscheck` clean.

**FALSIFIER:** any green-at-base gate red on the pilot, any new pin_crosscheck collision/stale
verdict, any `source_pin_drift` from wiseman_osim under store resolution → THE DESIGN IS WRONG,
stop. Phase-3 shrink < 300 MB or any receipt pin failing against store bytes → THE CLAIMED WIN
IS WRONG, blobs return to git, store keeps future acquisitions only.

## 3. The store design (Deliverable 3)

### 3.1 Layout — a plain content store

```
E:/ChimeraData/                       <- CHIMERA_DATA_STORE points here
  store/<sha256[0:2]/<sha256[2:4]>/<sha256>>   <- immutable blob, exactly the bytes git held
  index/chimera_data_index.json       <- committed in-repo (append-only), the mapping:
       entries: [{ logical, path_in_git_at_registration, sha256, bytes,
                   class: RAW|DERIVED, dataset, registered_utc, registered_by,
                   provenance: download_receipt | sha256_manifest | <receipt path>,
                   status: active | superseded }]
  tmp/                                <- staging; rename() into store/ is atomic
```

- **No database, no server.** sha256 → path is pure arithmetic; the index manifest is the only
  state, it is committed to the repo, and it is append-only (a wrong entry is `superseded`, not
  edited) — the same discipline receipts already follow.
- Logical names stay repo-shaped: `wiseman2026/Primate_models.zip`,
  `morphosource_ct/meshes_preview/bone_04_180534vox_lo.obj` — receipts keep citing repo-relative
  paths, so nothing about the receipt language changes.
- Duplication is free: two logical names with identical bytes share one store object.
- GC is a no-op by construction while the committed index is append-only; a later GC lane may
  only drop blobs absent from every active index revision.

### 3.2 Resolution layer — one small module, nothing breaks before migration

`tools/science_funnel/data_store.py` (NEW, ~60 lines, proposed — not written by this lane):

```python
def resolve(rel, must_exist=True, pin=None):
    """rel is the repo-relative path under tools/science_funnel/data/ as receipts cite it today.
    Order: (1) in-repo path tools/science_funnel/data/<rel>  (today's default, nothing migrated);
           (2) $CHIMERA_DATA_STORE/store/<sha> when the committed index maps <rel> to a sha;
           (3) refusal naming the missing artifact (never a silent empty read)."""
```

- Env var: `CHIMERA_DATA_STORE` (absolute path to `E:/ChimeraData` or a mirror). Unset →
  in-repo behavior only. **Before any migration the module is a no-op wrapper**, so landing it
  cannot break a single gate — its falsifier is the pilot.
- The seam: funnel code already funnels path reads through `common.py::local_file(root,
  relative)` or `DATA = ROOT/'...'` constants; the resolution layer wraps `local_file`, and the
  six `DATA=` constants become `data_store.root()` one-liners at migration time.
- Pins stay pins: when the caller passes the expected sha (as `wiseman_osim.pinned_bytes`
  already does), `resolve()` verifies store bytes against it before handing the path over.
  A store blob whose sha IS the address cannot drift; the check protects the index mapping, not
  the bytes.
- DERIVED outputs written back into data/ (only `matter_skeleton_import.py` today) keep landing
  in-repo first — the repo remains the origin of derived proof bytes; registering them into the
  store is a separate, later registration step, never a silent redirect of writes.

## 4. What HISTORY means here (Deliverable 4) — said with numbers, honestly

1. **The byte-stability law** (`.gitattributes`: `tools/science_funnel/data/** -text`, plus
   per-dir `-text -whitespace` refinements born of the CRLF lessons, instance 1–3 recorded in
   `wiseman_pin_repair_20260921/receipt.json`). Preserved because: content addressing means a
   store blob cannot differ from what git held — the sha256 in the index IS the address; and
   paths that remain in-repo keep the `-text` rules untouched. After a path leaves git, the
   index entry + receipt pin carry what `-text` carried: checkout-invariant bytes.
2. **Receipts' sha pins.** Preserved because receipts never change language: they keep citing
   `science_funnel/data/...` paths and 64-hex sha256s; `pin_crosscheck.py` keeps scanning them;
   `wiseman_osim.pinned_bytes` keeps enforcing. The resolution layer resolves the SAME logical
   path to store bytes and verifies them against the SAME sha before use.
3. **Verify-by-fresh-clone.** Preserved and sharpened: a fresh sparse clone must still prove
   every gate. Post-migration, "fresh clone" gains a store prerequisite — the falsifier's
   phase-3 clause requires the clone-size delta to be measured AND every pin re-verified from
   store bytes, not assumed.
4. **Append-only receipts / no history rewrite.** Blobs already committed stay in git history
   forever; nothing is rewritten, no filter-branch, no force. **The honest win is therefore not
   repo size** — it is (a) per-checkout duplication: every new lane clone stops paying 259 MB of
   pack + 353 MB of checkout for datasets that no acquisition lane will ever re-read from git,
   and (b) future acquisitions: the next wiseman-scale corpus (94.6 MB raw+extracted) lands in
   the store from day one with git holding only receipts — the pattern wiseman and
   visible_monkey already practice by hand, now with a resolution layer that makes it uniform.
5. **Evidence is not the target.** `docs/evidence/` looks like the problem (8.7 GB logical) but
   packs to 95.4 MB because near-identical proof frames delta-chain; it is RECEIPT-EVIDENCE by
   law and stays in git. A design that migrated evidence would spend real risk to win 95 MB.
   The data dir is the opposite: 352.6 MB logical → 259.1 MB packed (73%), because zips and tifs
   do not compress. **We migrate the number that is real.**

## 5. What makes this riskier than it looks

- **In-flight acquisition lanes are writing under `tools/science_funnel/data/`** (two
  prestage lanes at design time). Phase 2/3 must coordinate via the operator: a dataset whose
  lane is in-flight does not migrate. The pilot is immune (wiseman lane is DONE).
- **The store is machine-local.** `E:/ChimeraData` lives on this workstation; a fresh machine
  needs the store seeded (re-fetch via receipts) or a copy. Mitigation designed in: every index
  entry carries `provenance` (URL/record) so `data_store.py --fetch <logical>` can rebuild a
  dataset from upstream; the wiseman receipt already proves this route works.
- **Checkout asymmetry**: lanes that sparse-checkout heavily (like this clone) may lack index
  updates unless the index ships with the repo — it does, by design (committed, small).
- **Two-truths window**: between "blob registered in store" and "blob gitignored", both copies
  exist. The order is always register → verify (sha) → switch resolution → gate → then ignore.
  Never delete the in-repo copy before its gate runs green on store resolution.
- **`matter_skeleton_import.py` writes back into data/** — if its inputs ever move to the store
  while its outputs stay in-repo, its read side must resolve through the layer. Phase 2 includes
  this switch explicitly.
