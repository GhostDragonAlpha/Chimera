REPO HOOK CONVENTION (inspected before writing code, per packet):
  * .git/hooks/pre-commit is HOST-level (pi-shazam auto-installs and
    rewrites it; it also skips every non-main branch, so it never runs on
    astra/* task branches).
  * A REPO-LEVEL hook mechanism EXISTS and is enabled:
    `core.hooksPath = .githooks`, tracked at .githooks/pre-commit and
    .githooks/commit-msg. .githooks/pre-commit is the canonical wiring

    from the repo root (e.g. `python -m core.bind_guard --staged`,
    `python tools/doc_lint.py --staged`), with a WHY comment.
  * Therefore the guard ships as: script `tools/agent_fleet/
    evidence_log_guard.py` (mode `--staged`, repo convention) + a
    warn-only stanza appended to .githooks/pre-commit. NO new hook
    infrastructure is invented; nothing existing is weakened, removed,
    or bypassed (the shazam delegation and every existing gate stanza
    stays byte-for-byte intact).
