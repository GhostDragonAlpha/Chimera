## The forensics class being fixed

`.gitattributes` at base carries `* text=auto`; with `core.autocrlf=true` (this fleet's
Windows default) every text file under docs/evidence/** is LF-normalized into the blob
but REWRITTEN to CRLF on checkout. Any sha256 recorded for such a file therefore stops
verifying on any fresh Windows checkout (PR #73 review LOW-1; same root as PR #69's
gen-2 HIGH where 181 verdict flips were checkout artifacts, not measurements).

## Deliverable 3 — the renormalization retrospective (measured, not guessed)

For every sampled text file: (a) does the BLOB contain CRLF bytes? (b) does the
recorded hash equal the blob hash (LF form) or the CRLF rendering of the checkout?
"Predates the rule" = a recorded hash matching a CRLF rendering while the blob is LF
(that file's recorded hash describes a pre-rule checkout artifact and needs a one-time
renormalization + re-record). The one-time implication is documented for future lanes:
after the rule, re-adding a pre-rule working file still holding CRLF bytes would commit
those bytes verbatim (blob flips LF->CRLF) — pre-rule evidence files must be
re-checked-out under the rule (byte-exact) before any touch; `git add --renormalize`
is a no-op for -text paths (no conversion either way), so the discipline is
re-checkout, not renormalize.

## STATEMENT (theory, per RULE 0)

`docs/evidence/** -text` makes every recorded evidence hash checkout-invariant: the
bytes a reviewer hashes are the bytes every author committed, on every platform,
forever — evidence stops depending on the reader's git config.
