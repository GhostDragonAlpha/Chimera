## REFERENCE MODEL CONTRACT (fixed before implementation)

A self-contained stdlib-only module (gov06_reference_model.py, inside this
evidence scope, importing NOTHING from the repository) implementing the
INTENDED catalogue-discovery contract - what the card promises, not what
the deployed interceptor happens to do:

- state: imports ledger (APPEND-ONLY list of {digest, imported_revision,
  epoch}); current import {digest, payload, imported_revision, epoch,
  leader}; tasks{id: state, realized_from}; revision counter.
- catalogue_import(lead, epoch, digest_echo, payload): lead+epoch gate;
  when an import is current the caller must echo its digest (else refusal
  stale_catalogue_import); payload validated (cards: id, status, deps;
  malformed -> invalid_catalogue_payload:*); digest RECOMPUTED from the
  payload (caller-claimed digest never trusted); same-digest re-import ->
  duplicate_catalogue_import; ledger APPENDS (history never rewritten).
- catalogue_next(digest): unknown digest -> unknown_catalogue_digest;
  frontier = cards where status=='PROPOSED', id neither live nor done,
  and EVERY depends_on satisfied by an INTEGRATED realization - intended
  dependency mapping: a card X is satisfied by an INTEGRATED task whose
  realized_from == X; the fleet's documented realization-id convention is
  'holodeck-' + card-id lowercase (per the draft's own id derivation), so
  satisfaction is checked through the mapping, never by raw string luck.
- supersede/contradict/promote: APPEND-ONLY workflow records. promote()
  refuses (speculative_not_certifiable) unless a lead-authorized lifecycle
  trail exists for the card: an INTEGRATED task realized from it. Catalogue
  operations NEVER create, claim, admit or mutate tasks - a card is
  planning data and grants no authority (the card falsifier, enforced).
