In the frozen engine service (ZERO C++ edits), the water vis plane is not a
tint: `water_vis.comp` emits REAL DISPLACED GEOMETRY — every wet cell's
triangle, displaced by depth d = V*Q/A along its own normal, fixed water
blue. The v1 judge saw "a small blue patch" because the substrate was the
CREATURE's surface and the pour landed at the TOP cell, so only a thin cap
ever existed. If the same public routes are fed a PLANAR FLOOR substrate —
a triangulated disc derived at runtime in Python and appended to the
creature mesh (one /mesh_bin composite; the disc block is the water part) —
then the identical vis plane renders a POOL: injected water spreads
radially (the CA equalizes surface height bed+h; on a flat disc bed is
constant, so flow is pure spreading) and the level RISES (displacement
grows with V). Water becomes a visible, measurable BODY with a rising
level in the room — delivered entirely through Python + public HTTP.

The v1 judge's spec, addressed item by item:
  (a) visible water body — pool/rising level, not a neck tint:
      -> floor-disc substrate; pool on the room floor around the creature.
  (b) the pour START must be on-screen:
      -> the tap opens mid-capture; consecutive captured keyframes straddle
         it (dry+armed with steps_total==0, then counting from 0 with the
         floor still dry, then first water). Nothing happens between
         keyframes; the HUD truth (/state hud.water) is machine-read at
         each keyframe.
  (c) spreading must be progressive between consecutive keyframes:
      -> keyframes chosen so EVERY consecutive pair strictly increases
         sum(V), wet cells, rendered water vertices, and pool level.
  (d) cryptic injection readout:
      -> the C++ HUD string is frozen; the humanized companion (caption
         strips composed by Python from engine-truth reads) ships in the
         proof folder and the result record, clearly marked as
         Python-composed. The BLIND judge frames stay clean (no captions —
         captions naming water would prime the judge).

D3  Disc resolution and shape: an axis-aligned SQUARE-GRID disc clipped to

    cell, winding CCW seen from +Y so cell normals are +Y up). Quad side
    s = sqrt(2 x A_mean), A_mean = mean(areas of SALLY_body_0), so each
    disc TRIANGLE (the actual water cell) has area exactly A_mean — the
    measured scale of the solver constants (checked at derivation time:
    the measured ratio is 1.0000). The staircase rim of a clipped grid

    substrate's own dual-edge law, so the disc is a closed basin — water
    cannot leak past the rim.

    walk climbs unboundedly (853 colors measured at derivation time —
    a kernel-launch blowup for the color-serial solver: one pass per
    color per step). The law's CONTRACT is: edges sharing a cell get
    DISTINCT colors, chosen deterministically in the canonical edge

    The solver contract is preserved; the color COUNT is a feasibility
    fix, not a physics change.
