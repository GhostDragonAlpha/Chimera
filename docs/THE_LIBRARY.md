## How to admit the next database

The admission path is the batch pipeline: one command connects the
database, integrates every record and proves the whole batch against
per-class mechanical contracts in one run with one receipt:

```
python -B -m tools.creature_graph.batch_qualify \
    --admit <connector_id>[,...] --reprove all --train exercise \
    --out tools/science_funnel/validation/<lane>/receipt.json [--apply]
```

- connectors: `tools/science_funnel/batch/connectors*.py` (artifact
  pins resolve at load time from each data dir's
  `download_receipt.json` -- never hardcoded, never guessed)
- per-class contracts: `tools/creature_graph/data/authored/
  class_contracts.json` (each contract carries its own statement,
  prediction, falsifier and mechanical checks; the store refuses a
  record whose class contract is unknown or version-drifted)
- the whole-batch count identity, quoted from the embedded source
  receipts above: "fetched == admitted + quarantined + conflicts,
  zero silent drops"
- without `--apply` everything runs on scratch and nothing is
  written into the authored program; with `--apply` the merge goes
  through the one serial writer and the store is rebuilt
