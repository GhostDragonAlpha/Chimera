**THE THEORY DELIVERED (lead, same day):**
- **Core insight: the worktree isn't the problem — the FILE is.** A worktree is a workaround for one design error: the unit of change (a file) is coarser than the unit of meaning (a law). N agents editing N different laws in different units never conflict BY CONSTRUCTION — no isolation needed because nothing shared is mutated. The walk spine conflicts only because all laws live in one gait_controller.hpp.
- **Layer 1 — the Lego brick = the addressable law-unit** (one law per record/file/graph-node, not twelve laws per .hpp). WE ALREADY INVENTED THIS FOR THE RUNTIME: the matter kernel IS this philosophy (membranes as units, bonds as the only connection, joint classes as cited records) — the project's body is a Lego system with a universal stud; development never turned the philosophy on itself.
- **Layer 2 — the universal connection = THE RECEIPT PROTOCOL** (already standardized): inputs as hashes + outputs as hashes + a claim + a falsifier. Bricks snap when hashes match and falsifiers compose (the AND of two claims, verified once). The missing piece: source changes as TYPED PATCHES — functions of state ("the carrier fire reads the other's hold-clear"), not positions ("line 442") — merge becomes verification, not text adjacency.
- **Layer 3 — the shared bucket: content addressing everywhere** (git blobs already; receipts/sha pins already; the data-store pilot for datasets; the completion = a shared content-addressed BUILD CACHE, output = hash(inputs+flags), so ten agents share 95% of build artifacts).
- **Layer 4 — the worktree dies, replaced by the MATERIALIZED VIEW**: a disposable lens (sparse checkout of exactly the needed hashes over the shared store + shared build cache), destroyed on completion — projection, not isolation. Sparse clones (2.2GB w34) are the halfway proof; the janitor already treats worktrees as scaffolding-not-storage.
- **The genuinely-uninvented piece: position-independent, semantically-addressed edits** (CRDTs did it for text; nobody did it for LAWS). But the version we need doesn't require the full invention — per-law granularity + content addressing + receipt-as-stud gets the whole project parallel without worktrees using only pieces this project already built.
- **What stays serial honestly:** the walk spine's derivation ORDER (wave N's measured death names wave N+1's law — causality, not tooling), and the single master merge gate. But with per-law units, RACES become the norm (many laws in flight on one shared recorded state, wave-27-style, for every membrane at once).

Also delivered same day, the current parallel/serial division (asked directly): **parallelism = file-disjointness** — serial = the walk spine (one law per wave, one file, byte-exact reproduction gate), each lane's prereg→mine→build→measure order, integration (one merge-by-hash pass), the articulation lineage; parallel = lanes on disjoint substrates, races on sibling branches, the lead's verification desk (reproductions never block dispatch, they gate only the merge), hard serialization points = master itself, port 8127, each worktree's own build.
