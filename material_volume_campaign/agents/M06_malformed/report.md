## 6. Findings (all flagged runs, honestly classified)

**F-1 (harness, fixed — false CRITICAL-DEFECT).** F05 unregistered mutation; see §5.

**F-2 (harness, fixed).** C01/C04/C05/C06 preregistered the decimal literal `1e400` ("parses to float
inf" → runtime `nonfinite_input`), but a Python-level mutation serializes `float('inf')` as the
NONSTANDARD `Infinity` token, which exercises the reader class (`input_read_error`) — the same class
as C02/C03/C07 — not the preregistered runtime class. First pass therefore showed 6 WRONG-NAME runs.
Fix: `TEXT_FIX` writes the literal bytes `1e400` (verified: `json.loads('1e400')` → inf, so the value
reaches the runtime `_number` check). Final pass: all four cases NAMED-REFUSAL `nonfinite_input`,
exactly as preregistered. Both refusal names are real and reachable; the tools are correct.

**D-1 (DEFECT — SILENT-PASS, exit-signal class). E03 exp and G10 exp: the exporter exits 0 for
malformed source-authority inputs.** The admission CLI refuses both (exit 2:
`missing_segment_authority` / `duplicate_identifier`). The exporter recomputes admission, carries the
named refusal in `admission_reason_codes`, emits NO mass (falsifier negative), but classifies the
report `export_status: "unsupported"` (because `mass_authority` is source-effective) and therefore
exits 0 — a shell-success signal for malformed input. The preregistered expectation was named refusal
+ nonzero exit. Severity: NOT mass leakage (no mass emitted; refusal named in the report body); it is
an exit-classification defect: the doc's `blocked` status ("reconstructed-mass admission failed; body
properties are not exported") arguably fits a refused admission better than `unsupported`, and would
exit 1. Itemized as defects per the brief. Decision request for the owner: should a refused admission
under source authority be `blocked` (exit 1) rather than `unsupported` (exit 0)?

**D-2 (finding — WRONG-NAME). G04 exp: exporter refuses `unknown_group_cell_id` where the matrix
expected `duplicate_cell_id`.** Mechanism: renaming partition cell-B to cell-A removes cell-B from the
partition, so the exporter refuses — correctly per its own doc ("refused: … missing group cell") — on
the downstream effect; partition-internal duplicate detection is admission's job (adm exit 2,
`duplicate_cell_id`, correct). Exporter: named refusal, exit 1, no mass. Finding: cross-layer refusal
naming differs for one malformed document; no silent pass.

**D-3 (finding — EXIT-DEVIATION / matrix erratum). H04 adm: exit 2 vs preregistered 1.** The admission
doc says unknown region references "cause a named refusal; they are never remapped" — the tool sets
decision `refused` (exit 2) with `compiler_refusal.reason = unknown_region` and
`unknown_region_reference` in reason_codes, exactly matching the doc's wording. The matrix's predicted
exit class (1 = not_admitted) was misderived at freeze time. Tool doc-consistent; matrix expectation
erratum. Decision request: amend the frozen matrix line for H04 (or confirm exit-2 as intended).

**Doc-ambiguous verdicts: none.** Every case's outcome was decidable against the two docs and the
preregistered expectations.
