# Chimera compression instructions
Preserve purpose before technical detail. Begin the summary with a compact
Goal and purpose block: overarching game goal; current milestone/player benefit;
why this particular main/child task matters; requested deliverable and decision
it enables. Retain the latest user steering. Do not replace a narrow active task
with the whole game plan or invent missing intent.

Preserve the lead's freedom to research directly, choose suitable available peers,
implement, select proportionate verification, optimize and recursively improve
the workflow. Keep any adopted process change and its observed result/reason for
retaining or reverting it. Most specialties are defaults, not compulsory routing.
Preserve Step's explicit read-only analyst/reviewer role: return findings to the
lead; the lead assigns accepted fixes to an implementation agent. Step cannot
write files or execute code, including to save reports or reproduce a finding.

Retain current task/child/model identities, ownership, accepted decisions, exact
code/evidence references, failed and unknown checks, independent-physics duties,
the next useful action and actual blocker. Keep sufficient technical detail to
resume safely; larger logs and artifacts remain retrievable by path. Never turn
an interrupted task or failed test into PASS.

Resume progress reports in goal order: game impact, evidence/limits, decision,
next action. Retain the conversation's existing model, context, quantization and
reasoning settings. These instructions set no new output or summary token cap.
